Four days after the finals ended, I made the last decision. What to keep and what to delete.

---

## Background: One Promise Was Still Outstanding

When we set the key rules during the first integration test of the preliminary round, I had said: "I'll reissue it. Record it so the reissue notice comes up at wrap-up." We had decided to keep key copies only in the designed injection paths (the gateway's credential store, the sandbox supervisor process, the NemoClaw settings), and in exchange, to revoke the keys once the competition was over.

## What We Did

| Target | Handling |
|---|---|
| NVIDIA API keys (preliminary and finals) | **Revoked** (by me) |
| Brev cloud instance | **Deleted** (by me) |
| Finals sandbox, credential bundles, sandbox image | Deleted |
| Preliminary sandbox, OpenShell, NemoClaw | Removed |
| Gateway state folder, NemoClaw settings, copies of the sealed data, `.env` | Deleted (by me) |
| Hackathon Docker images and containers | Deleted |
| colima and Docker data from other projects | **Kept** — in use since before the hackathon |
| Preliminary and finals repositories | **Kept** — published results and a record |

Some deletions weren't done by the agent but by me directly. The agent's auto-approval mechanism blocked deleting the state folder in the home folder as an "irreversible deletion." The agent didn't work around what was blocked; it handed over the exact commands, and I ran them myself. I think it's right that a person presses the last button on anything irreversible.

## Deferred Work Gets Closed as Unresolved

The finals state record had five deferred items: cleaning up working branches, polishing the on-screen warning list, leaving slack for time comparisons in the demo script, screenshots for the public repository, and the issue of commit author emails being public. We only cleaned up the branches and marked the rest **complete as unresolved**. We also decided not to do the Codex re-review of the preliminary PRs. What I said was, "I'm not doing any more work in git."

## Options

| Plan | Judgment |
|---|---|
| Leave the environment as is | Dropped — key copies and unused resources remain |
| Delete everything, including the project folders | Dropped — local records not in the repository (run outputs) would disappear |
| Finish the deferred work | Dropped — the competition is over, and merging means publishing |
| **Delete the runtime environments and key copies, keep the records, close remaining work as unresolved** | **Adopted** |

## What I Learned While Cleaning Up

While cleaning up, I followed the order for shutting down the Docker virtual machine again. I stopped the gateway first, then turned on colima, deleted only the hackathon data, and turned it off once the work was done. It was to avoid repeating what happened the night before the finals, when turning colima off right after turning it on left the sandboxes stuck in Error.

## Looking Back

What lasts longest from the two hackathons is not the code but the way of deciding.

- Lock in the evaluation first, and don't change the rules after seeing the results.
- Draw boundaries with code instead of instructing the model.
- Leave decisions as records, not in chat.
- Don't write about what we didn't build as if we had built it.
- A person decides anything irreversible.

This series was also written based on those records.
