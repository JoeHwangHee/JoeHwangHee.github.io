정오 무렵 정한 구조는 이랬다. 질문이 들어오면 먼저 무게를 판단하고, 가벼우면 바로 답하고, 무거우면 코스·유래 조사 구조를 탄다.

---

## 처음 결정(12시)

내가 지시한 원문은 이렇다.

> 1. 질문이 들어왔을 때 질문의 무게를 확인하기 위해 Claude API를 붙여 진행시킴
> 2. Claude API는 질문의 무게만 판단(응답 실패 시 폴백, 응답 불가)
> 3. 무거운 질문일 시 개발된 구조를 사용
> 4. 데이터베이스는 인덱싱된 데이터를 저장(프로젝트 안에 JSON으로)

이어서 두 가지를 더 정했다. 가벼운 질문은 Nemotron이 자료 없이 답하고 "자료 근거 없음(일반 안내)"을 붙인다. Claude 판단이 한 번 다시 보낸 뒤에도 실패하면 추측하지 않고 "응답 불가"로 끝낸다.

## 문제: 평가 환경에는 Claude 키가 없다

구현이 진행되면서 문제가 보였다. 심사자가 우리 저장소를 받아 돌리는 환경에 Claude 키가 없으면, 라우터가 실패하고, 규칙대로 **모든 요청이 "응답 불가"**가 된다. 정작 NVIDIA 기술로 만든 본체는 한 번도 불리지 않는다.

## 선택지

| 안 | 판단 |
|---|---|
| 환경변수로 Claude 판단 건너뛰기(권장안) | 버림 — 건너뛰면 무게 판단 자체가 사라진다 |
| 키가 없을 때만 자동 전환 | 버림 — 두 경로를 다 유지·시험해야 한다 |
| 그대로 | 버림 |
| **라우터를 Nemotron으로 교체** | **채택** |

내 답은 짧았다. "Claude가 아닌 Nemotron으로 변경(최우선)."

## 바꾼 것

- 제품은 Claude를 부르지 않는다.
- 두 정책 파일에서 Claude 메시지 API 허용 블록을 지우고, 샌드박스에 Claude provider를 붙이지 않는다.
- 실행 기록의 칸 이름과 호출 한도 이름도 `router`로 바꿨다.

정책에서 Claude를 지우니 외부 전송 허용 목록이 하나 줄었다. 외부로 나가는 길이 적을수록 권한 설계를 설명하기도 쉬워진다.

## 이 선택의 의미

**데모는 남의 환경에서 돌아야 한다.** 개발자 노트북에서만 도는 구조는 심사에서 의미가 없다. 그리고 NVIDIA 해커톤에서 핵심 판단을 다른 회사 모델에 맡기는 구조는, 기술적으로 가능해도 이야기로서 약했다. 라우터 교체는 재현성과 이야기를 함께 바로잡은 결정이었다.

## 그 뒤

오후 늦게 팀이 Brev(NVIDIA GPU 클라우드)에 띄운 vLLM 엔드포인트도 쓸 수 있게 했다. 기능 동결 뒤의 변경이라 범위를 좁혔다. 키 변수 이름을 고르는 설정 하나와, 정책 파일에 앱 Python만 쓸 수 있는 vLLM 블록 하나만 더했다. 샌드박스 안에서 vLLM으로 가벼운 질문에 답하고, OpenShell 로그에 그 경로가 허용된 기록이 남는 것을 확인했다.
