공개 전환 직전에 오케스트레이터가 라이선스를 정해야 한다고 했다. 나는 물었다. "라이선스는 뭘 말하는 거야?"

---

## 배경: 공개와 허가는 다르다

설명은 이랬다. 저장소가 공개돼 있어도 **LICENSE 파일이 없으면 다른 사람에게 재사용·수정·재배포 권리를 주지 않는다.** GitHub 안에서 보고 포크하는 것만 가능하다. 공개 저장소를 제출하면서 "가져다 써도 되는가"에 대한 답이 비어 있는 셈이었다.

## 선택지

| 안 | 판단 |
|---|---|
| 라이선스 없음 | 버림 — 보는 것만 가능하고 쓸 권리가 없다 |
| MIT 같은 짧은 허용형 | 가능했지만 특허 조항이 없다 |
| **Apache-2.0** | **채택** — 허용형이면서 특허 조항이 있다 |

오케스트레이터의 권장은 Apache-2.0이었다. 허용형이면서 특허 조항이 있고, NVIDIA 공식 스킬 생태계의 표기와도 맞는다(추론). 나는 "라이선스는 권장대로할게"라고 답했다.

## 적용 범위

루트에 Apache License 2.0 전문을 넣고, README에 범위를 적었다. **이 프로젝트가 만든 코드와 문서에만 적용**되고, 관세청 통계나 BACI 같은 제3자 자료는 각 출처의 조건을 따른다. 스킬 세 개의 거버넌스 카드도 공식 생성기로 다시 렌더해 라이선스 표기를 맞췄다.

## 같은 새벽의 확인 두 가지

- **실제 NIM 조사**: 오케스트레이터에게 담당자 화면의 "조사 시작"을 실제로 눌러 보라고 했다. 실자료 경보 1건이 13.1초 만에 완료됐고, 모델 요청 5회 모두 HTTP 200, 보고서 숫자 대조 7개 일치, 키 흔적 0건이었다.
- **교육 미션 요건**: 강의 수료가 필수인지 다시 물었다. 공식 페이지 원문은 "교육 미션을 확인합니다"였고, 수료를 요구하거나 증빙을 받는다는 문구는 공식 페이지·신청 폼·도움말 어디에도 없었다. 앞서 "9월 27일까지 들어야 한다"고 한 설명은 로드맵의 내부 일정을 공식 기한처럼 적은 오류였고, 바로잡았다.

## 이 선택의 의미

공개는 "보여 주는 것"이고 라이선스는 "쓰게 해 주는 것"이다. 해커톤 결과물이라도 남이 가져다 쓸 수 있어야 공개의 의미가 완성된다. 같은 새벽, 이 프로젝트의 개발 순서와 선택 이유를 한 문서로 남기는 기획·개발 일지도 만들었다. 이 블로그 시리즈의 바탕이 된 문서다.
